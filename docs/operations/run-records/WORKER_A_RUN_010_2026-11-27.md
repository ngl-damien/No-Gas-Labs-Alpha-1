## Institutional fluency — one useful distinction

**Established term: process-restart persistence test.** It verifies that a defined state survives termination and recreation of a process when the same durable storage is reused. It is not the same as multi-device synchronization, multi-instance consistency, or end-to-end user acceptance.

**NGL framing:** a “continuity proof” is useful only when its boundary is explicit: what state, which process boundary, which storage, and which exact evidence.

- Plain English: “We proved this saved collaborator response survives restarting the game server; we did not prove two servers or two phones stay in sync.”
- Technical/research: “The test rehydrates the event from the same data directory after process recreation and checks byte-identical retained provenance and idempotent replay.”
- Skeptical defense: “Show me the test's process boundary and storage setup. A restart test on one server is not evidence of multi-instance consistency.”

**Tiny exercise:** classify each claim as process-restart persistence, multi-client shared-process behavior, multi-instance consistency, or physical-device acceptance. Do not promote one category into another.
